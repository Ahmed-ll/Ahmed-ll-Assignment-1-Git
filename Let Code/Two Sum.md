انا كنت استخدمت ف الاول حل ولكنه كان هيكون كارثة لانه `O(n²)` 
ودا لانه مبني علي استخدام nasted loop ف استبعدته تماما واستبدلته ب كود بيستخدم Dictionary عشان اقدر اخد Time Complexity افضل 

---

ببساطة، الكود فكرته قائمة علي إننا بنمشي على الـ `nums` مرة واحدة

وكل مرة بناخد الرقم الحالي ونحسب الرقم اللي محتاجينه عشان نوصل للـ `target` وده اسمه **complement**. 

يعني لو `target = 9` والرقم الحالي `2`، يبقى الـ complement هو `9 - 2 = 7`

فبدل ما نلف على كل الـ array وندور على `7`، بنستخدم `Dictionary` اسمه `map` بيخزن كل رقم قابلناه قبل كده مع الـ index بتاعه بالشكل دا `number → index`.

في البداية بيكون الـ `map` فاضي، نبدأ بالرقم `2`، نحسب إننا محتاجين `7`، نسأل الـ Dictionary هل `7` موجود؟ ف يقولنا لا، فنخزن `2 → 0`.

بعد كده نتحرك للرقم `7`، نحسب الـ complement بتاعه فنلاقي `9 - 7 = 2`
نسأل الـ Dictionary هل `2` موجود؟ يقولنا اه موجود، ومتخزن عندي في index `0`، والرقم الحالي موجود في index `1`، لذلك نرجع `[0, 1]`.

وسبب إننا بنعمل `ContainsKey` **قبل** تخزين الرقم الحالي، عشان نبحث بس في الأرقام اللي قابلناها قبل كده.

وبدل ما نستخدم loop داخل loop ونوصل لـ `O(n²)`، إحنا بنستخدم Dictionary والبحث فيه متوسطه `O(1)`

---

احنا بنمر على الـ array مرة واحدة لذلك **Time Complexity = `O(n)`**
